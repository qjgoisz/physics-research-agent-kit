# 理论物理科研技能使用指南

## 先理解技能如何生效

Codex 技能是包含 `SKILL.md` 和可选支持文件的目录。技能可用时，Codex 会先看到技能的名称和描述，并据此决定是否加载完整说明；用户也可以在提示词中明确指定技能名称。三个技能的官方结构和本仓库设计都遵循这一机制。

相关说明：

- [OpenAI Skills 文档](https://developers.openai.com/api/docs/guides/tools-skills)
- [OpenAI Build skills 文档](https://developers.openai.com/plugins/build/skills)

本仓库目前只保存技能源文件，没有把它们自动安装到个人 Codex 配置，也没有发布插件。

## 安装到个人 Codex 技能目录

如果希望在其他 Codex 项目中自动发现这三个技能，可把三个完整目录复制到个人技能目录。先创建目标目录：

```bash
mkdir -p "${CODEX_HOME:-$HOME/.codex}/skills"
```

然后在本仓库根目录执行：

```bash
cp -a skills/physics-research-explore "${CODEX_HOME:-$HOME/.codex}/skills/"
cp -a skills/physics-research-numerics "${CODEX_HOME:-$HOME/.codex}/skills/"
cp -a skills/physics-paper-writing "${CODEX_HOME:-$HOME/.codex}/skills/"
```

复制后应得到：

```text
${CODEX_HOME:-$HOME/.codex}/skills/
├── physics-research-explore/
│   └── SKILL.md
├── physics-research-numerics/
│   └── SKILL.md
└── physics-paper-writing/
    └── SKILL.md
```

建议重新开启一个 Codex 会话，使技能清单重新加载。不要复制 `templates/theoretical-physics-research/`：它是内部维护模板，不是可发现技能。

如果只想在本仓库开发和验证技能，可以不安装；直接让 Codex 阅读相应路径下的 `SKILL.md` 即可。

## 显式调用

显式调用最可靠，尤其适合阶段切换或同时存在多种可能工作流时。可以直接使用技能名：

```text
使用 $physics-research-explore，阅读 reference/ 中的资料，核验相关工作，并把当前想法整理成一个可证伪的研究问题。解释按研究生量子力学和统计物理水平展开。
```

```text
使用 $physics-research-numerics，先审查 README.md、RESEARCH-STATE.md 和 Results.md，再运行有限尺寸收敛检查。保存原始数据和图片，并更新 Results.md。
```

```text
使用 $physics-paper-writing，按 PRL Regular Article 的要求编辑这份稿件。先核验当前官方作者指南，建立 Writing-Guide.md，然后检查所有定量主张和引用。
```

如果当前界面不使用 `$技能名` 语法，也可以写成：

```text
请使用 physics-research-numerics 技能完成下面的任务……
```

## 自动触发

安装后，Codex 会根据请求和 `SKILL.md` 的 `description` 判断是否使用技能。通常不必手动指定：

| 用户目标 | 应触发的技能 |
|---|---|
| 阅读论文、解释理论、核验推导、形成研究问题 | `physics-research-explore` |
| 跑模拟、分析数据、画图、做误差或收敛检查 | `physics-research-numerics` |
| 起草论文、编辑稿件、核验期刊规范、审稿式检查 | `physics-paper-writing` |

当请求跨越多个阶段时，建议明确指定当前优先交付物。例如，“先完成理论复现并形成数值计划，不要开始大规模计算”应使用调研技能；“理论已经确定，现在只做可复现的参数扫描”应使用数值技能。

## 推荐的项目准备

新项目可以从内部模板复制以下文件到项目根目录，并删除不适用的空节：

```text
AGENTS.md
RESEARCH-STATE.md
Results.md
Writing-Guide.md
```

模板位于 `templates/theoretical-physics-research/`。探索技能还自带 `README.md` 和 `RESEARCH-STATE.md` 的输出模板；数值技能自带 `Results.md` 模板；写作技能自带 `Writing-Guide.md` 模板。

不要机械覆盖已有项目文件。项目已有成熟结构时，应保留其语言、目录和构建约定，只补充缺失的信息。

## 推荐的三阶段工作流

### 1. 调研阶段

给出研究起点和期望解释水平。起点可以是一篇论文、已有笔记、一个物理系统、一个异常结果或一个模糊想法。

推荐提示词：

```text
使用 $physics-research-explore。我的背景是凝聚态理论研究生，熟悉二次量子化和格林函数，但不熟悉 Keldysh 技术。请先检查 reference/ 中已有论文，区分已读证据和未核验背景，再解释模型并提出两个可证伪的研究问题。最终更新 README.md 和 RESEARCH-STATE.md，不要开始生产级数值模拟。
```

预期产物：

- 明确的研究问题和研究缺口；
- 经核验的文献与推导；
- toy model；
- 分析与数值计划；
- 更新后的 `README.md` 和 `RESEARCH-STATE.md`。

### 2. 数值阶段

开始前确保项目状态、模型、参数、约定和主要可观测量已经写清楚。技能会先审查项目并检查 `Results.md`，避免在存在阻塞性问题时盲目计算。

推荐提示词：

```text
使用 $physics-research-numerics。先读取 README.md、RESEARCH-STATE.md 和 Results.md，检查哈密顿量、边界条件和代码约定是否一致。若没有阻塞问题，计算能隙随系统尺寸的标度，至少做三组尺寸的收敛比较，保存代码、参数、原始数据和矢量图，并把可复用结果按物理问题写入 Results.md。
```

预期产物：

- 可重复执行的代码和精确命令；
- 参数、种子、原始数据和图；
- 已知极限、收敛性和不确定度检查；
- 更新后的 `Results.md` 与 `RESEARCH-STATE.md`。

### 3. 写作阶段

提供目标期刊、文章类型和希望 Codex 承担的角色：起草、重构、语言编辑或审稿检查。若目标期刊尚未确定，可以先让技能比较候选期刊，但不要把未经核验的投稿要求写成事实。

推荐提示词：

```text
使用 $physics-paper-writing。目标是 Physical Review B Regular Article。请先从官方来源核验当前投稿要求并更新 Writing-Guide.md，然后编辑 results.tex。保持现有物理结论不变，核对每个数值主张与 Results.md 的对应关系，统一术语和符号，最后给出未解决的审稿人意见清单。
```

预期产物：

- 有来源和核对日期的 `Writing-Guide.md`；
- 与项目证据一致的稿件修改；
- 术语、符号和风格一致性检查；
- 引用与定量主张追溯结果；
- 公开的审稿人式问题清单；
- 更新后的 `RESEARCH-STATE.md`。

## 混合任务如何处理

一个请求可以涉及多个技能，但应按依赖顺序处理：

```text
文献与理论是否站得住
        ↓
数值结果是否可复现、可相信
        ↓
论文主张是否可追溯、适合目标读者
```

如果理论定义仍有阻塞性歧义，不应直接进入大规模计算；如果数值主张没有可追溯结果，不应通过写作把它包装成确定结论。可以让 Codex先完成一个阶段并建议交接，也可以明确授权同一任务按顺序使用多个技能。

示例：

```text
先使用 $physics-research-explore 核验 Eq. (12) 的推导；确认无阻塞问题后，再使用 $physics-research-numerics 做最小数值交叉验证。暂时不要修改论文。
```

## 如何判断技能是否正确工作

调研技能应主动区分已核验和未核验内容，并把想法写成可失败的问题；数值技能应在计算前读取项目状态，保存复现信息，并按物理问题更新结果索引；写作技能应核验官方投稿来源、显示术语台账和未解决的审稿意见，而不是只做表面润色。

如果技能没有触发：

1. 确认技能目录下直接存在 `SKILL.md`。
2. 重新开启会话以刷新技能发现。
3. 在提示词中显式写出 `$physics-research-explore`、`$physics-research-numerics` 或 `$physics-paper-writing`。
4. 检查任务是否其实属于相邻技能。

如果触发了错误技能，应先修改相应 `SKILL.md` 的 `description`，使用户目标和排除边界更明确，再用 `docs/validation-report.md` 中的五类请求重新测试。

## 更新技能后重新验证

在本仓库根目录运行：

```bash
/usr/local/miniconda3/bin/python /home/debian/.codex/skills/.system/skill-creator/scripts/quick_validate.py skills/physics-research-explore
/usr/local/miniconda3/bin/python /home/debian/.codex/skills/.system/skill-creator/scripts/quick_validate.py skills/physics-research-numerics
/usr/local/miniconda3/bin/python /home/debian/.codex/skills/.system/skill-creator/scripts/quick_validate.py skills/physics-paper-writing
```

如果已经把技能复制到个人目录，修改仓库版本不会自动更新已安装副本。验证仓库版本后，需要重新复制对应目录，或采用你自己的同步流程。不要让个人安装副本成为无人维护的分叉版本。
