# 理论物理科研预设迁移说明

## 迁移目标

本项目将原 DSH 理论物理科研预设家族改写为三个职责清晰、可以独立安装和触发的 Codex 技能：

1. `physics-research-explore`：文献调研、概念讲解、理论推导、结果复现、研究想法评估与问题设计。
2. `physics-research-numerics`：数值模拟、数据分析、绘图、收敛与误差验证、可复现性和结果索引。
3. `physics-paper-writing`：论文起草与编辑、投稿要求核验、术语和风格一致性、主张可追溯性及审稿人式检查。

原来的通用科研预设没有继续作为第四个技能发布。它现在位于 `templates/theoretical-physics-research/`，只用于设计和维护未来的科研技能，不参与技能发现，也不会被安装到 Codex 的全局技能目录。

## 目录结构

```text

├── physics-research-numerics/

templates/
```

每个技能都是自包含的：运行时不依赖其他技能、内部模板或原 DSH 源目录。技能入口保留核心判断规则，条件性细节放在 `references/`，可复用的项目文档骨架放在 `assets/`。

## 三个技能的使用边界

### 调研与问题设计

当目标是理解一个主题、核对文献、复现理论推导、解释物理机制，或把模糊想法整理为可证伪的研究问题时，使用 `physics-research-explore`。

这一阶段的完成标准不是得到大量计算结果，而是形成：

- 明确的物理问题；
- 经核验的相关工作与研究缺口；
- 最简单且定义完整的 toy model；
- 可检查的理论假设；
- 后续分析和数值工作的具体计划。

### 数值模拟与结果管理

当目标是运行模拟、分析数据、制作图表、检查收敛性和误差，或建立可复现的数值结果时，使用 `physics-research-numerics`。

开始计算前应先阅读项目状态与已有结果，核对理论、代码和约定是否一致。重要结果必须保留生成代码、原始数据、参数、命令、随机种子、误差或不确定度以及验证方法，并通过 `Results.md` 统一索引。

### 论文写作与审阅

当目标是撰写或编辑论文、核验投稿要求、统一术语和语言，或者进行审稿人式检查时，使用 `physics-paper-writing`。

技能要求投稿规则来自当前官方来源，并记录网址和核对日期。所有定量主张必须能追溯到 `Results.md`、已记录推导或经验证的外部来源；引用不仅要真实存在，还必须支持其所附着的具体陈述。

## 统一的科研状态分类

三个技能都使用同一套状态分类，避免后续接手者从语气中猜测可信度：

- `established`：由已检查的推导或经核验的来源支持；
- `verified numerically`：由可复现的数值计算及明确验证支持；
- `plausible`：有合理依据，但尚未完成验证；
- `conjecture`：有意保留、尚待检验的研究假设；
- `unknown`：当前没有结论或证据不足。

如果理论推导、代码、数值结果或文献彼此不一致，应把这种不一致作为需要调查的发现，不能为了得到预期结论而隐藏、调参或静默改写。

## 项目文档约定

迁移后的技能采用以下分工：

| 文件 | 用途 |
|---|---|
| `AGENTS.md` | 稳定、简洁的 Codex 仓库指令，不记录频繁变化的研究进度。 |
| `RESEARCH-STATE.md` | 面向后续 Agent 的研究交接，记录状态分类、决定、未决问题、文件地图和下一步。 |
| `README.md` | 面向人的项目概览，记录中心思想、相关工作、创新点、toy model 和研究计划。 |
| `Results.md` | 按物理问题组织的数值结果总索引。 |
| `Writing-Guide.md` | 单篇论文的投稿要求、术语、符号和语言风格契约。 |

原 DSH 约定中的 `Agents.md` 不再兼任仓库指令和研究交接。技能仍会读取已有项目中的 `Agents.md` 与 `Readme.md`，但新项目应优先采用上表中的标准名称。

## `Results.md` 的基本要求

`Results.md` 必须按研究内容或物理问题组织，而不是按日期排列。每项值得保留的结果至少应包含：

- 结果名称、物理含义和可信状态；
- 主要图片的相对链接；
- 原始数据的相对链接；
- 生成结果的代码链接；
- 参数文件或关键参数；
- 精确运行命令和随机种子；
- 收敛、已知极限、对称性或其他验证；
- 不确定度以及被替代关系。

临时调试输出、无独立意义的中间文件和失败探索不进入结果索引。

## 写作契约

`Writing-Guide.md` 应记录：

- 目标期刊与文章类型；
- 官方作者指南的网址和核对日期；
- 投稿前必须重新核验的易变规则；
- 禁止直接进入论文的内部术语；
- 首次出现时必须定义的术语；
- 统一拼写、大小写和措辞；
- 各部分的时态、人称和行文风格；
- 符号、单位和有效数字约定；
- 尚未解决的主张或引用问题。

完成草稿后还应进行一次怀疑性的审稿人检查，明确列出缺少的对照、替代解释、过度主张、数值伪影、图文不符和遗漏的相关工作。未解决的问题必须向用户公开，而不是藏在修改过程里。

## 与原 DSH 预设相比的主要变化

保留的内容包括科研可信度分类、文献与引用核验、数值可复现性、分歧调查、结果索引、术语与风格台账、投稿来源核验以及审稿人检查。

被重新设计的内容包括：

- 把单一大型 persona 拆为三个按用户目标触发的技能；
- 把 `Agents.md` 的研究交接职责迁移到 `RESEARCH-STATE.md`；
- 把条件性指导和输出模板从技能入口中分离；
- 把固定环境假设改为使用时检查。

有意删除的内容包括 DSH 注册表、Cordis bundle、生成器与安装流程，`dsh-defend` 的拒绝语义，以及固定的 Python、TeX、MATLAB、Wolfram、GPU、硬件、路径和版本信息。这些内容要么属于 DSH，要么容易过时，要么已经由 Codex 的上层权限和安全规则处理。

具体安装、调用和三阶段使用示例见 [`使用指南.md`](使用指南.md)。逐节处置结果见 [`migration-map.md`](migration-map.md)，完整验证记录见 [`validation-report.md`](validation-report.md)。

## 验证与维护

修改技能后，应分别运行内置验证器：

```bash
/usr/local/miniconda3/bin/python /home/debian/.codex/skills/.system/skill-creator/scripts/quick_validate.py skills/physics-research-explore
/usr/local/miniconda3/bin/python /home/debian/.codex/skills/.system/skill-creator/scripts/quick_validate.py skills/physics-research-numerics
/usr/local/miniconda3/bin/python /home/debian/.codex/skills/.system/skill-creator/scripts/quick_validate.py skills/physics-paper-writing
```

还应检查：

1. 所有 `SKILL.md` 引用的文件都存在于对应技能内部。
2. `templates/theoretical-physics-research/` 中不存在 `SKILL.md`。
3. 已安装技能没有指向内部模板或原 DSH 路径。
4. 三个技能的描述仍能区分相邻但不应触发的请求。
5. 没有重新引入固定环境事实或 DSH 专属权限假设。

本仓库只维护技能和非安装型模板，不负责全局安装、Codex 配置修改或插件发布。
